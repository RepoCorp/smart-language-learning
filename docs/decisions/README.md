# Decisions

This directory contains decisions that should remain available to humans and coding agents across conversations and implementation sessions.

Use a decision document when a choice has been explicitly accepted and is likely to affect future product or engineering work.

A useful lightweight structure is:

- **Status** — proposed, accepted, superseded, or deprecated.
- **Context** — the problem or constraint that led to the decision.
- **Decision** — what was decided.
- **Consequences** — important implications, tradeoffs, or follow-up work.

Not every decision needs a formal ADR number. Prefer clarity over ceremony.

The [definition-driven learning-content decision](definition-driven-learning-content.md)
records the accepted structure, registration boundaries, and incremental migration
approach for the new definitions and playground.
